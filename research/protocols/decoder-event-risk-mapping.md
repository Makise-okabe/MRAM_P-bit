# Decoder-event risk mapping: software discovery protocol
Date: 4 November 2026, Asia/Singapore.

Scope: F3 mapping with F1 supporting estimator. This is a conditional mathematical
prototype, not an executed MNIST or target-circuit experiment. No novelty pass.

Fixed questions:
1. Can an exact decoder-event calculation rank equal-read row permutations by
   classification failure when a Gaussian surrogate using exact margin moments ranks
   them differently?
2. Does a cached update after changed reads match a complete event reconstruction?
3. Is that update actually faster than an already vectorized complete reconstruction?
4. What does DIB-CIM verifiably control, and which method details are inaccessible?

Evidence contract:
- Use binary weights and one resident permutation shared by every output.
- Keep exact count-support bounds, signed margin reconstruction, persistent factor
  identity, and ideal arithmetic.
- Use a declared bounded synthetic row-response factor; no fitted GF parameters.
- Include zero/full-column affine calibration as an explicit control.
- A counterexample is an existence result. It is not an independent task benchmark.
- Report unchanged simple comparators, including ones that match the proposed choice.
- Do not call an input-statistics comparator a DIB-CIM reproduction. Its full text
  and exact mode/threshold policy remain unavailable in this environment.
- Preserve the separate complementary-read certificate proposal. Do not count its
  proof as validation of the mapping estimator, or force an extra runtime read.

This prototype tests a fixed affine output head with a scalar latent factor. A
conditional extension to higher-dimensional persistent variation requires sampling
the remaining factors and charging that cost. Non-affine hidden-layer propagation
requires a separate implementation.

No train/validation/test data or NUS machine is accessed. Future MNIST work must use
the frozen checkpoint/quantizers, CAL parent IDs only for selecting maps, independent
evaluation parents and chip realizations, and a newly validated read/decoder operator.


## Follow-up: event-influence screening

The optimized vectorized full-rebuild control removed the initial cached-table speed
advantage. A further specific rule was derived: the probability mass where changed
decoder outputs alter a class margin bounds a candidate's maximum reliability
improvement. Use that bound to discard candidates that cannot beat the incumbent.
Verify skipped candidates afterward and include all bound costs in runtime. The
constructed 81-candidate screen skips 71 safely but is slower overall in its tiny
two-read case. Preserve that negative result; no parameter sweep to advertise a win.
