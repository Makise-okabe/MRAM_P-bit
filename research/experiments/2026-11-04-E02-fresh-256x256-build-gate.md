# E02 fresh-target-array build gate — 2026-11-04

**Decision:** Begin a new physical 256 x 256 MRAM-CIM array study. Historical 8-cell/small-array readout results are **excluded** from all target current distributions, calibration fits, model tuning, ADC thresholds, validation and claimed gains. Retired records stay archived for reproducibility only; their numerical read results must not be re-imported.

## Scope boundary: actual array versus bookkeeping
- Target: 256 physical rows x 256 physical bit positions = 65,536 binary MTJ positions. Weight bit-plane mapping must be declared separately.
- A 256 x 256 NumPy matrix alone is **not** a physical array.
- Batching rows in software does not isolate long BL/SL wires.
- Claims of shorter sectors need real isolation devices, connectivity and local/peripheral sensing models.
- A schematic-expanded full electrical array with independently validated interconnect equivalents is a *model*; label it accordingly. A fully extracted 256 x 256 macro requires its actual layout, DRC/LVS and parasitic extraction. Do not conflate the two.

## E02-a: choose and verify the physically viable cell
1. Audit the authorized MTJ and access-transistor source, pin order, model interfaces, bias restrictions and licensing.
2. Make an explicit 1T1MTJ versus foundry-native 2T1MTJ topology decision based on layout legality, read margin, write current, selection and sensing—not transistor count alone.
3. Verify P/AP operation and one selected versus unselected read on the **new** target model only; generate all target calibration anew.
4. Keep proprietary sources in the authorized NUS environment; store only portable scripts, model-port specifications and nonrestricted measurements.

## E02-b: declare electrical 256x256 macro architecture
Record full row/column cell connectivity; BL, SL and WL distribution; drivers; 256-column simultaneous activity and peripheral sharing; ADC/sense interface and operating points; read time; selected/unselected loading; spatial/device/common mismatch and repeat-read noise sources.
For any sector candidate, specify actual isolation switches, local and global wires, and local/shared readout. Freeze comparator hardware for fair runs.

## E02-c: validate a real electrical response
1. Build and DRC/LVS-check a repeatable tile, e.g., 16x16 or 32x32, using the chosen cell; extract representative wire/device parasitics.
2. Create a 256x256 hierarchy with concrete wire lengths, unselected loads, row drivers and sense nodes. Use a full schematic/netlist model where feasible; any reduced equivalent must be independently validated against extracted tiles and later longer-wire cases.
3. Test KCL, transistor headroom, read-current decoding, BL/SL/WL settling and cross-column interference.
4. After safe preflight, select two parallelism points and 12-24 **new** nominal patterns (zero/sparse/medium/dense; near/middle/far; P/AP mix), then held-out patterns; these counts are intended budgets, not completed experiments.
5. Only then introduce **new** persistent mismatch assignments and separately supported temporal noise. Preserve each fixed device assignment across reads and input planes.

## Gating before E03 and E09
- E01 real workload occupancy can proceed independently as software evidence, but is not circuit validation; it cannot supply an MRAM read-error law.
- E03 covariance-aware mapping may use constructed E03M only as a mathematical counterexample. Test actual *decoded* pair moments with E02-calibrated readout before an MRAM-specific claim.
- E09 p-bit/Ising calculations are a separate possible application. Stable eMRAM is not itself a proven stochastic p-bit; target local-field operators and reference digital incremental baselines must be declared.
- Fail the physical gate if no legally/physically valid cell, no tractable wire/sense path, unsafe current/voltage, unsupported fan-in, or no held-out response-model agreement.
